小波子带分解（DWT）

一次小波变换把图像拆成四个频带：LL 保留整体轮廓，LH/HL/HH 分别保留水平、垂直、对角细节。这就是 JPEG2000 没有方块效应的秘密。

LL 低频（轮廓）
LH 水平细节
HL 垂直细节
HH 对角细节

它为什么没有方块效应

01

JPEG 的罪：8×8 分块

JPEG 把图像切成 8×8 的小块，每块独立做 DCT 变换。块与块之间各自为政，压缩狠了，块边界就露出明暗差——就是那个难看的「马赛克」方块。

02

JPEG2000 的解：整图小波变换

DWT 对整张图做全局变换，不切块。图像的能量被重排到四个频带里，压缩时只是「粗化」某些频带，不会有块的边界，所以没有方块效应。

03

多分辨率是白送的

小波分解天然产生一个「缩小的 LL」子带。于是同一个文件里既装着全图，也装着半分辨率和 ¼ 分辨率的版本——渐进式加载、缩放看细节都不用重新下载。

那它到底输在哪

技术全面占优，却输给了市场：核心算法被商业机构注册了大量专利，授权费用劝退了浏览器和操作系统；DWT 计算量是 DCT 的 10~20 倍，编码更慢；最致命的是——JPEG 已经无处不在，没有「硬伤」，没人愿意为一个「更好一点点」的东西重建整个生态。技术最先进 ≠ 技术能赢。

核心代码（教学版 Haar 小波）

// 一维 Haar 小波：把数组拆成低频(平均)+高频(差异)
function haar1d(arr) {
  var n = arr.length, half = n >> 1, out = new Float32Array(n);
  for (var i = 0; i < half; i++) {
    out[i]      = (arr[2*i] + arr[2*i+1]) / 2;  // 低频
    out[i+half] = (arr[2*i] - arr[2*i+1]) / 2;  // 高频
  }
  return out;
}

// 二维 DWT = 先对每行做 1D，再对每列做 1D
// 结果自然分成 LL / LH / HL / HH 四个频带

真实 JPEG2000 用更复杂的 9/7 或 5/3 小波 + EBCOT 熵编码，这里是保留其灵魂的教学等价物——用最简单的 Haar 小波，让你「看见」DWT 的核心思想。

它没死，只是换了个地方活着

数字影院（DCI）

好莱坞数字放映的标准格式，4K/8K 母版用 JPEG2000 编码。这里没有兼容性包袱，画质和帧率优先。

医学影像（DICOM）

CT、MRI 影像要求无损存档 + 任意缩放看细节。JPEG2000 的无损能力和多分辨率正好对口。

卫星遥感 / 档案扫描

超大图像需要渐进式加载和快速缩放，正是 JPEG2000 多分辨率特性的主场。

互联网？几乎绝迹

浏览器默认不支持、没有生态、编码慢。它输掉的，恰恰是它最该赢的战场。
