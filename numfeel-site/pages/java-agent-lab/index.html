培养舱实况：一个 Java Agent 正在监视这个服务

Go/Node 把程序编译成「罐头」，Java 把程序养在「培养舱」里。这个页面就是培养舱的观察窗： 一个核心插桩不足百行的 Java Agent（ByteBuddy 插桩）挂在正在服务这个页面的后端进程上， 把方法调用（耗时 ≥ 10µs）的耗时、线程、异常记下来——业务代码一行都没改。

原理：agent 是怎么「不碰代码」改掉代码的

全部魔法集中在类加载的一瞬间，磁盘上的 jar 和源码仓库自始至终没有被打开过。

1. 内联插桩

agent 注册一个 ClassFileTransformer；每个类被加载时，JVM 把原始字节码递给它， ByteBuddy 用 @Advice 把「进入记时间 / 退出算耗时」几行指令原地拷贝进方法体。 不生成代理类、不改方法签名。

2. shade + relocate

ByteBuddy 自身被改名打包进 agent jar（shaded.bytebuddy）， 与业务 classpath 上任何版本的 byte-buddy 物理隔离——这是所有生产级 agent（OTel、Arthas）的标准姿势。

3. 数据回流

事件写进进程内的环形缓冲，agent 自带一个只绑定 127.0.0.1 的 HTTP 接口； 对外只靠一个两个 GET 方法的转发 controller。读者把 agent 挂到任何 Spring 项目上，同样三步就能复现。

对照实验：在本页地址后面加上 ?api=http://localhost:8080（指向你本地服务）， 再给你的服务挂上 trace-agent.jar（仓库 trace-agent/ 目录，./mvnw package 一条命令构建）， 你自己的服务也能被这样「开天眼」。 SkyWalking / OpenTelemetry 的 javaagent 就是这个机制的产品化。
