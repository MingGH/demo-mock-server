小波子带分解（DWT · 原理示意）

下面是教学用 Haar 小波示意 DWT 的子带结构（真实 JPEG2000 用 9/7 或 5/3 小波，分解出的频带结构相同）。一次变换把图像拆成四个频带：LL 保留整体轮廓，LH/HL/HH 分别保留水平、垂直、对角细节——因为小波作用在整张图上、不切块，所以压缩时不会产生 JPEG 那种方块效应。

LL 低频（轮廓）
LH 水平细节
HL 垂直细节
HH 对角细节

它为什么没有方块效应

01

JPEG 的罪：8×8 分块

JPEG 把图像切成 8×8 的小块，每块独立做 DCT 变换。块与块之间各自为政，压缩狠了，块边界就露出明暗差——就是你在上面放大图里看到的马赛克方块。

02

JPEG2000 的解：整图小波变换

DWT 对整张图做全局变换，不切块。图像能量被重排到四个频带里，压缩时只是「粗化」某些频带，没有块的边界，所以没有方块效应。

03

渐进式是白送的

码流可以组织成多个质量层 / 多分辨率层。同一个文件，解码器读前段得低画质、读越多越清晰——上面的渐进演示就是真实码流的层解码。

那它到底输在哪

技术全面占优，却输给了市场：核心算法被商业机构注册了大量专利，授权费用劝退了浏览器和操作系统；DWT 计算量是 DCT 的 10~20 倍，编码更慢；最致命的是——JPEG 已经无处不在，没有「硬伤」，没人愿意为一个「更好一点点」的东西重建整个生态。技术最先进 ≠ 技术能赢。

技术实现：真实编解码，不是模拟

// 真实 JPEG2000 编码：OpenJPEG（编译成 WebAssembly，浏览器内运行）
// 内部使用 9/7 小波（有损）+ EBCOT 熵编码，输出真实 J2K 码流
encoder.getDecodedBuffer({ width, height, componentCount, bitsPerSample, isSigned }).set(pixels);
encoder.setDecompositions(3);        // 小波分解层数
encoder.setQuality(false, 1);        // 有损编码
encoder.setCompressionRatio(0, 12);  // 目标压缩比 12:1
encoder.encode();                    // 输出真实 J2K 码流

// 真实 JPEG 编码：直接用浏览器原生 encoder（canvas.toBlob 的 image/jpeg）
canvas.toBlob(cb, 'image/jpeg', quality);  // 8×8 DCT + 色度下采样

// 渐进式：一个码流 6 个质量层，逐层真实解码
decoder.decodeSubResolution(0, layer);     // layer = 1..6

上面的压缩对比、体积、PSNR、渐进层都是真实编解码结果：JPEG 用浏览器原生编码器，JPEG2000 用 OpenJPEG（WASM）。唯一「示意」的部分是上方小波子带分解图——真实编码器不暴露中间系数，所以用 Haar 小波展示相同的频带结构。

它没死，只是换了个地方活着

数字影院（DCI）

好莱坞数字放映的标准格式，4K/8K 母版用 JPEG2000 编码。这里没有兼容性包袱，画质和帧率优先。

医学影像（DICOM）

CT、MRI 影像要求无损存档 + 任意缩放看细节。JPEG2000 的无损能力和多分辨率正好对口。

卫星遥感 / 档案扫描

超大图像需要渐进式加载和快速缩放，正是 JPEG2000 渐进/多分辨率特性的主场。

互联网？几乎绝迹

浏览器默认不支持、没有生态、编码慢。它输掉的，恰恰是它最该赢的战场。
